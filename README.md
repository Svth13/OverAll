# OverAll

Цель проекта:
Разработать инструмент, который на основании данных из существующей таблицы учёта стажёров автоматически формирует информацию о количестве стажёров у каждого техлида в течение выбранного месяца и предоставляет данные, необходимые для расчёта оплаты овера конкретного техлида.
15.10 в папке app - черновик веб-приложения, которое нужно затестить после поднятия инфраструктуры.
создана новая версия **`Парсинг_v5.ipynb`**
14.10 Репозиторий содержит скрипты для парсинга данных из Google Таблицы с информацией по стажерам, технологиям, техлидам, датам старта/стопа и причинам статусов.

В проекте два основных сценария:

1. **`Парсинг_v4.ipynb`** — формирование ежемесячного отчета для расчета оплаты:
   - ежедневное количество активных лаборантов по технологиям и техлидам;
   - сводка за месяц;
   - учет неоплачиваемых отпусков.

2. **`Парсинг_снепшот_v2.ipynb`** — создание снепшотов данных и отслеживание изменений:
   - ежедневный срез текущего состояния таблицы;
   - сохранение истории в `history.csv`;
   - фиксация добавленных, удаленных и измененных записей в `changes_log.csv`.

## Скрипты умеют:

- читать основные листы таблицы;
- читать отдельный лист с промежуточными статусами стажеров;
- очищать и нормализовать ФИО, технологии и даты;
- отфильтровывать некорректные служебные значения;
- строить ежедневный отчет по активным лаборантам;
- учитывать неоплачиваемые отпуска;
- формировать ежемесячную сводку для расчета оплаты;
- создавать снепшоты данных;
- сравнивать текущий снепшот с предыдущим;
- сохранять журнал изменений.

## Структура репозитория

```text
.
├── Парсинг_v4.ipynb              # Расчет ежемесячного зарплатного отчета
├── Парсинг_снепшот_v2.ipynb      # Создание снепшотов и журнала изменений
├── credentials.json              # Файл доступа к Google API, не коммитить!
├── snapshots/                    # Папка со снепшотами и историей
│   ├── snap_YYYY-MM-DD.xlsx      # Дневной снепшот
│   ├── history.csv               # Сквозная история всех снепшотов
│   └── changes_log.csv           # Журнал изменений
└── payroll_report_YYYY_MM.xlsx   # Ежемесячный отчет для оплаты
```
## Основные возможности

Парсинг_v4.ipynb
Ноутбук формирует отчет для расчета оплаты за выбранный месяц. 

Результатом работы является файл вида
`payroll_report_2026_10.xlsx`

Внутри которого создаются два листа:
- `Ежедневный_отчет`;
- `Сводка_за_месяц`.

Основные возможности:
* парсинг основных листов таблицы;
* парсинг листа Промежуточный статус стажера;
* нормализация названий технологий;
* очистка ФИО техлидов и лаборантов;
* фильтрация некорректных техлидов;
* конвертация дат из разных форматов;
* учет периодов неоплачиваемого отпуска;
* расчет количества уникальных лаборантов по дням;
* агрегация данных за месяц;
* выгрузка результата в Excel.


### `Парсинг_снепшот_v2.ipynb`

Ноутбук создает снимок текущего состояния таблицы и сохраняет его в локальную историю.

Основные возможности:

- сбор данных из всех основных листов;
- сбор данных из листа промежуточных статусов;
- приведение данных к единому формату снепшота;
- сохранение ежедневного Excel-файла;
- ведение сквозной истории в CSV;
- сравнение текущего состояния с предыдущим снепшотом;
- фиксация изменений:
    - `добавлен`;
    - `удален`;
    - `изменен`.

Результаты сохраняются в папку `snapshots/`:
```
snapshots/snap_2026-10-14.xlsx
snapshots/history.csv
snapshots/changes_log.csv
```

## Настройка доступа к Google Sheets

Скрипты используют аутентификацию через Google Service Account.

### 1. Создайте проект в Google Cloud

Перейдите в [Google Cloud Console](https://console.cloud.google.com/).

Создайте новый проект или выберите существующий.

### 2. Включите API

Необходимо включить:

- Google Sheets API;
- Google Drive API.

### 3. Создайте Service Account

1. Откройте раздел `IAM & Admin` → `Service Accounts`.
2. Создайте сервисный аккаунт.
3. Создайте ключ в формате JSON.
4. Скачанный файл положите в корень проекта под именем: `credentials.json`
### 4. Откройте доступ к Google Таблице

В самой таблице нажмите `Поделиться` и добавьте сервисный аккаунт как читателя.

Адрес сервисного аккаунта находится внутри `credentials.json` в поле: `"client_email":`
